### 关于 IPMI（这次唯一的「新发现」）

这台机器装了 IPMI 驱动，一开始看起来有希望：

```
IPMIDRV: status=Stopped, startType=Manual
  -> Start-Service 成功，状态变为 Running
  -> 驱动文件 C:\Windows\System32\drivers\ipmidrv.sys 存在
  -> WMI 类 IPMIPrv / IPMIDRIVER 均存在
```

但进一步检查发现是**空壳**：

```
IPMIPrv     : 0 instance(s)      <- 类存在，但没有实例
IPMIDRIVER  : 0 instance(s)      <- 同上
两个类都未暴露任何方法
```

**结论**：Windows 自带的 `ipmidrv.sys` 是通用驱动，只有主板真正挂了 BMC 并提供 IPMI 系统接口（通常对应 ACPI 的 SPCR 表 + 板载管理芯片），才会有实例。这台机器 0 实例，说明**带内 IPMI 通道不存在**——要么主板没配 BMC，要么 BIOS 里关闭了。

补充：扫描网关 `192.168.1.100` 的 623/443/80/8443 全部超时，未发现 BMC 管理口。

> 关于 IPMIDRV 驱动：它是内核驱动，标记为 `NOT_STOPPABLE`，`sc stop` 返回 1052 无法停止。
> 但它的启动类型是 `Manual`，**重启后会自动回到 Stopped**，不构成残留影响。

### 关于 SuperIO

```
Hygon SMBus              PCI\VEN_1D94&DEV_790B   [OK]
PCI standard ISA bridge  PCI\VEN_1D94&DEV_790E   [OK]
System board             ACPI\PNP0C01\C8
Motherboard resources    ACPI\PNP0C02\90 / \91 \700
```

`VEN_1D94` 是**海光（Hygon）的 PCI 厂商 ID**。温度与风扇通常由 SuperIO 芯片（ITE/Nuvoton/Fintek）提供，通过 I/O 端口 0x2E/0x4E 访问。但 LHM 只认识主流消费级 SuperIO 型号，海光这套平台上的实现既没被枚举成独立设备，也没有公开的寄存器文档，无法安全读取（盲读可能写坏寄存器）。

## 三、根因总结

这台机器是**信创平台**：

- 主板：`Suma 22DC4_2`（曙光系）
- 系统型号：`Suma T40`
- CPU：海光 Hygon C86-3G，`AMD64 Family 24 Model 2`
- BIOS：`HYGON - 2` / `CZYH052906` / 2025-04-14

海光基于 AMD Zen 授权，但温度读取走的是厂商私有寄存器接口。该平台的固件既没有实现 ACPI 热区，也没有开放 SuperIO 或 IPMI 到操作系统的通路。**这不是权限问题（全程 SYSTEM + elevated），也不是软件缺陷——OS 层面确实没有任何入口。**

## 四、如果一定要拿到温度

按可行性排序：

1. **找曙光/中科可控要带外监控工具**（最靠谱）
   信创服务器通常配套 BMC 管理软件，`Suma T40` 应该有对应的管理口。先确认机器后面板是否有独立的管理网口（通常标 MGMT/iDRAC/IPMI），以及 BIOS 里是否禁用了 BMC。

2. **BIOS 里检查相关开关**
   进 BIOS 找 `IPMI`、`BMC`、`Hardware Monitor`、`Thermal` 相关选项，如果被禁用，开启后 OS 侧才可能看到传感器。

3. **带内 IPMI 工具（需先有 BMC）**
   若确认有 BMC，装 `ipmitool` 后：
   ```
   ipmitool -I lanplus -H <BMC_IP> -U <user> -P <pass> sdr
   ipmitool -I lanplus -H <BMC_IP> -U <user> -P <pass> sensor list
   ```
   能读到 CPU 温度、风扇转速、电压等完整数据。

4. **接受现状**
   CPU/内存利用率、磁盘 I/O、告警巡检都已正常工作。对日常运维判断来说，温度缺失不是致命项——尤其考虑到这台机器的两次非正常关机记录（Kernel-Power 41）更值得优先排查。
